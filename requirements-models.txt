# 1. torch first, matching your GPU. The dev machine is an RTX 5060 (Blackwell,
#    sm_120), which only the cu128 wheels support; cu121 silently has no kernel:
#        pip install torch --index-url https://download.pytorch.org/whl/cu128
#    CPU-only box (e.g. the Linode) instead:
#        pip install torch --index-url https://download.pytorch.org/whl/cpu
#    Never use the README's --extra-index-url .../whl/cpu alongside a CUDA build:
#    pip will happily replace the CUDA wheel with the CPU one.

# --- MOIRAI 2.0: why --no-deps ---------------------------------------------
# uni2ts 2.0.0 declares torch<2.5, numpy~=1.26.0, scipy~=1.11.3 and gluonts~=0.14.3.
# The torch/numpy/scipy pins are over-conservative — MOIRAI 2.0 loads and runs
# correctly on torch 2.11+cu128 / numpy 2.5 / scipy 1.18, verified on this project's
# context 65 / 32 / 16 shapes. Letting pip resolve them, however, downgrades torch to
# 2.4.1+cpu, which kills CUDA on Blackwell *and* breaks granite-tsfm (it requires
# torch>=2.10, pandas>=2.3.3). The two packages cannot coexist under normal resolution.
#
# The gluonts pin IS real: 0.17 changed `make_predictions`, and the MOIRAI predictor
# fails with "not enough values to unpack (expected 3, got 1)". Pin gluonts to 0.14.4.
#
